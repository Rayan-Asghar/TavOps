- **Migration numbers collided.** Another session took `0021` for `saved_views`
  while this branch was writing `0021` for the pipeline. Renumbered to `0022`;
  its journal `when` is later than `saved_views`', so file, journal and database
  order all agree. **Re-check `drizzle/` and `_journal.json` immediately before
  writing any new migration** — six sessions share this repo.
- **A dead notification kind is not free to revive.** `followup_due` survived the
  `0011` strip *and so did its rows*, on the same `followup:<id>` dedupe key.
  `notify()` upserts on `(user_id, dedupe_key)` and on conflict only clears a
  snooze — it does not rewrite title, body or the new `proposal_id`. Nine stale
  rows from August therefore **shadowed** every row the new sweep wrote: it
  reported `flagged: 9` and wrote nothing. Correct from the server, dead on the
  screen. `0022` deletes them; `tests/db/proposal-chase.test.ts` pins why.
- **A `"use server"` module may only export async functions.** `chaseDedupeKey`
  had to move to `proposal-schemas.ts` — the same reason every schema and label
  already lives there.
- **Bound parameters arrive untyped**, so a `CASE` built from them is `text` and
  `text * interval` is not an operator. `proposal-queries.ts` casts `::int`.
  The fixture test caught this; typecheck could not.
- **`work_log_costs` must never become columns on `work_logs`** — see
  `.claude/handoff-history/`, still true.
- **`drizzle-kit generate` models neither RLS nor CHECK constraints**, and it
